# 安全策略 / Security Policy

## 威胁模型（这个项目怕什么）

本项目的核心资产是**使用者本机的平台登录凭证**。安全目标只有一个：

> **凭证不出本机。** 脚本可以读凭证，但**绝不**把它发到非必要的第三方。

具体边界：

| 允许 | 禁止 |
|---|---|
| 本机读取 `*_cookie.txt` / 浏览器配置目录 | 上传凭证到任何远程服务器 |
| 带着凭证**直连平台官方域名**调接口 | 经任何中转/代理/统计服务转发凭证 |
| 日志打印脱敏后的掩码（`SCT1****6789`） | 日志打印完整 token / cookie / 设备号 |
| 推送**签到结果摘要**到使用者配置的通道 | 推送凭证、余额以外的隐私数据 |

> ⚠️ **唯一例外**：推送功能会把**签到结果摘要**发到使用者**自己配置**的通道
> （Server酱 / PushPlus / 企微 / 自定义 Webhook）。这是使用者显式开启的，
> 默认关闭；不配置 `notify.json` 时**零网络请求**。

## 已知安全设计（不是缺陷）

1. **`--capture` 走 CDP，不解密磁盘 Cookie。**
   现代 Chrome/Edge（≥127）的 App-Bound Encryption（`v20`）是**设计上的防护**。
   本项目用官方调试协议 `Network.getCookies` 让浏览器自己读自己的 Cookie，
   **没有绕过任何安全边界**，且只作用于本项目自建的独立配置目录。

2. **不碰日常浏览器数据。**
   所有浏览器操作都在 `.xxx_profile/` 独立目录中进行，
   不影响、也读不到使用者日常 Chrome/Edge 的登录态。

3. **不伪造设备号、不绕过风控。**
   使用真实设备标识；遇到风控失败即停，不做规避尝试。

4. **看板的写操作有 CSRF / DNS rebinding 防护。**
   本看板无认证，且浏览器发起的「跨源简单请求」（`text/plain` 的 POST）
   **不触发 CORS 预检**——请求会真正执行，只是响应被浏览器丢弃。
   这意味着仅凭「浏览器打开了一个恶意网页」就足以改掉手工余额。
   为此所有 POST 端点前置三道校验（`dashboard.py`）：

   | 校验 | 作用 | 失败响应 |
   |---|---|---|
   | `Host` 必须为回环地址 | 防 DNS rebinding | 403 |
   | `Origin`/`Referer` 若存在必须为回环地址 | 防浏览器跨源写入 | 403 |
   | 请求体 ≤ 64 KB | 防单条 POST 打爆内存 | 400 |

   **无 `Origin` 的请求（curl、计划任务脚本）照常放行**，不影响自动化调用；
   GET 只读端点不校验——数据本就是本机可见的，校验只会徒增干扰。

## 使用者须知（你的责任）

- **不要提交凭证**：`*_cookie.txt`、`notify.json`、`manual_balances.json`、
  `balances.json`、`*_profile/` 均含敏感数据，`.gitignore` 已屏蔽，
  但**提交前请自行 `git status` 复核**。
- **凭据只读不写回**：本项目不会修改你的凭证文件。
- **权限最小化**：凭证文件建议仅本人可读。

## 报告安全漏洞

如果你在本项目中发现安全问题（如凭证可能外泄、存在任意代码执行路径、
依赖被投毒等），请**私下报告**，不要公开开 Issue：

- 提交 **Gitee 私信 / Issue（标记为安全）**，或
- 通过仓库主页联系方式与我取得联系。

**请在报告中包含：**
1. 问题类型与影响范围；
2. 复现步骤（最小可复现示例最佳）；
3. 受影响的文件 / 版本；
4. 若有，附上修复建议。

**我承诺：**
- 在 **7 天内**确认收到并给出初步评估；
- 在修复发布前**不公开细节**；
- 在修复说明中**署名致谢**（若你希望匿名，请提前说明）。

## 支持范围

| 版本 | 安全修复 |
|---|---|
| 最新提交 / tag | ✅ 支持 |
| 历史版本 | ❌ 不保证 |

本项目的安全边界建立在**各平台接口现状**之上。若上游平台改变接口或风控策略，
相关模块**可能失效**——这属于功能限制，通常不构成安全漏洞，
但若失效方式导致凭证泄漏，请仍按上述流程报告。
